# GIF 动图分镜（maibot-plugin-gif-storyboard）

> 给麦麦补一块"动图视力"：**在 GIF 动图交给视觉模型之前，把各帧合成到同一张图上**，让视觉模型看到动画的内容与时序——而不是只看到第一帧。全部通过插件 SDK 实现，不改宿主一行代码。

- 插件 ID：`github.elmeir.gif-storyboard`
- 宿主要求：MaiBot ≥ 1.2.4（maibot-plugin-sdk ≥ 2.0）
- 依赖：Pillow ≥ 10.0.0（自动安装）
- 作者：[Elmeir](https://github.com/Elmeir) ｜ License：MIT
- 版本：见 [_manifest.json](_manifest.json) ｜ 变更见 [CHANGELOG.md](CHANGELOG.md)

## 功能

- **分镜合成**：检测消息中的 GIF 动图（文件头魔数识别），按时序均匀抽样（默认 9 帧 = 3×3 网格，可按运动量自适应）合成白底网格图，每帧带序号
- **识别保真**：替换 + 落库前恢复——视觉模型识别合成图，聊天记录与 WebUI 展示按原图保真
- **重复 GIF 零延迟**：同图重发直接复用已就绪的多帧描述，宿主跳过识别
- **精准作用域**：只处理普通图片组件（`type=image`）中的多帧 GIF；单帧 GIF、PNG/JPEG/WebP 等其他格式、表情包组件（宿主原生支持）零接触
- **安全放行**：解码失败、合成异常一律原样放行，绝不阻塞消息链

## 安装

```bash
cd /你的部署目录/plugins        # 例如 /opt/MaiBot/plugins
git clone https://github.com/Elmeir/maibot-plugin-gif-storyboard.git
# 重启麦麦（systemctl restart xxx / docker compose restart / 重启 bot.py）
```

> 目录名保持 `maibot-plugin-gif-storyboard`：配置存在插件目录内的 `config.toml`，换目录名会丢配置。

重启后在 WebUI 插件页确认「GIF 动图分镜（视觉增强）」已启用，配置项均有中文标签与说明，保持默认即可。

## 配置

### [merge] 帧合成

| 配置项 | 默认 | 说明 |
|---|---|---|
| 处理图片 | 开 | 处理普通图片组件中的 GIF（群友发的 GIF 主要走这里） |
| 最多帧数 | 9 | 超出上限按时序均匀抽样（含首尾帧）；帧越多信息越全，但图更大、token 更贵 |
| 最少帧数 | 2 | 帧数不足视为静态图，原样放行 |
| 自适应帧数 | 开 | 按动画运动量自动调节实际抽帧数：简单动画少抽（省 token），动作丰富的多抽 |
| 绘制帧序号 | 开 | 每帧标 1、2、3…，帮助 VLM 理解播放顺序 |
| 落库前恢复原图 | 开 | 识别完成后恢复原图，防止合成图进入聊天记录/WebUI |

### [output] 输出图像

| 配置项 | 默认 | 说明 |
|---|---|---|
| 输出格式 | jpeg | 体积小省 token（推荐）；png 无损但更大 |
| JPEG 质量 | 85 | 50~95 |
| 单帧格子边长上限 | 480 | 帧超过该尺寸等比缩小，控制合成图体积 |

### 表情包为什么不做

宿主表情链路原生支持 GIF 抽帧拼接分析（生成情绪标签）；插件旁路会造成双倍解析并破坏标签格式，v1.1.4 起表情组件一律原样放行。

## 边界与说明

- **多帧描述有延迟**：合成图由宿主后台异步识别，完成后自动回填进麦麦上下文；同图再次出现零延迟
- **描述搬运依赖 `database.query` 能力**（manifest 已声明）：能力缺失时合成图仍会被识别，但描述无法回填，视觉上退化为 GIF 首帧（日志有 warning）
- **与消息防抖插件共存**：钩子挂 `LATE` 槽位，防抖合并消息里的 GIF 也会被处理；合并转发里嵌套的图片暂不处理（仅顶层组件）
- **识别窗口内短暂替换**：从识别到落库前恢复（通常亚秒级）组件携带合成图，此窗口内进程崩溃会以合成图落库（概率极低，日志有 warning）
- 典型开销：9 帧 480px 合成图 JPEG 约 100~300KB，单次合成毫秒级，缓存命中零开销
